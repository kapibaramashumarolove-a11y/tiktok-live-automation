# TikTok LIVE 実連携の利用条件・実現可能性 調査レポート

- 調査日：2026年10月14日
- 対象：TikTok LIVE のコメント・ギフトなどのイベントを、本オーバーレイへ自動で取り込む方法
- 位置づけ：**調査結果にもとづく報告であり、規約への適合を保証したり、法的な判断を示したりするものではありません。** 実際に連携を行う前に、利用時点の TikTok 公式の規約・ガイドラインを確認し、必要に応じて TikTok への問い合わせや専門家への相談を行ってください。

## 1. 結論（要約）

| 方法 | 技術的に可能か | 規約上の懸念 | 本プロジェクトでの扱い |
|---|---|---|---|
| A. 公式 API による自動連携 | **提供されていない**（調査時点） | — | 実装しない（提供されたら検討） |
| B. 非公式ライブラリ（内部通信の解析）による自動連携 | 可能（既存ライブラリで短時間に接続できる） | **高い**：利用規約第5条で禁止されている行為に該当する可能性がある | **実装しない** |
| C. 非公式ライブラリを使う商用の中継サービス | 可能 | **高い**：B と同じ。CAPTCHA の自動解決をうたうサービスもあり、アクセス制限の回避に当たる可能性がある | **実装しない** |
| D. 配信者の手動操作（管理パネル） | 実装済み | 自動取得をしないため、B・C より懸念は小さいと考えられる（**未確認**） | **現在の運用方法** |
| E. 将来、公式の提供または TikTok の書面による許可が得られた場合 | アダプタを差し込める設計にしてある | 提供条件しだい | 接続口のみ用意（`src/sources/liveSource.js`） |

本プロジェクトは、規約上の懸念が小さい D（配信者の手動操作）を基本とし、自動連携は公式の手段が確認できるまで行いません。

## 2. 調査結果

### 2.1 公式 API（一次情報）

TikTok for Developers の製品一覧ページ（https://developers.tiktok.com/products/）を取得し、掲載されている製品を確認しました。

- 掲載製品：Share Kit、Login Kit、Content Posting API、Research API、Display API、Embed Videos、Data Portability API、Green Screen Kit、Commercial Content API、Mini Games・Mini Dramas（TikTok Minis）
- **LIVE 配信のコメント・ギフトをリアルタイムに取得する製品は掲載されていません。**
- Research API は、二次情報によると、対象地域の学術機関の研究者や一部の非営利団体に限られ、申請・承認が必要です。配信用オーバーレイでの利用を想定したものではないと考えられます（利用条件の詳細は**未確認**）。

二次情報（第三者の解説・ライブラリの説明）でも、「LIVE のチャット・ギフト・視聴者数などを取得する公開 API はない」とする記述が複数ありました。

### 2.2 非公式ライブラリ（二次情報）

| 名称 | 概要（各プロジェクトの説明による） |
|---|---|
| TikTok-Live-Connector（Node.js） | 「公式 API ではない」「リバースエンジニアリングのプロジェクト」と自ら説明。TikTok 内部の Webcast プッシュサービスに接続する。README では本番利用に適さないとし、本番用には第三者（EulerStream）の WebSocket API を勧めている |
| TikTokLive（Python） | 「非公式」と説明。配信者の `@ユーザー名` だけで接続でき、ログインやアプリ登録は不要とされる。ギフト（連続送信の処理を含む）・いいね・視聴者数などのイベントを扱う |
| 商用の中継サービス（例：tik.tools など） | WebSocket や Webhook で配信イベントを中継。署名の生成や **CAPTCHA の自動解決** を含むとうたうものがある |

技術的な特徴：

- TikTok の内部通信（非公開の仕様）を解析して接続しています。
- 接続には署名の生成が必要で、多くは第三者の署名サーバーに依存しています。無料枠は回数制限が厳しいとされています。
- TikTok 側の仕様変更で動かなくなる可能性があると、各プロジェクトが明記しています。
- 配信者本人でなくても、誰の配信にでも接続できる仕組みです。

### 2.3 利用規約（一次情報）

TikTok 利用規約の日本語ページ（https://www.tiktok.com/legal/page/row/terms-of-service/ja-JP）を取得しました。取得したページ上の表記では最終更新日は「2020年2月」で、**これが最新版かどうか、また日本の利用者に適用される版かどうかは未確認**です（英語版 ROW ページにも同じ趣旨の条項がありました）。

「5. お客様による本サービスのご利用」では、利用者がしてはならない行為として次のものが挙げられています（取得したページからの引用）。

- 「本サービスから情報を収集するために自動化されたスクリプトを使用することまたは本サービスと何らかの交信を行うこと」
- 「本サービスもしくはその派生物を構成するソースコード、アルゴリズム、メソッドもしくは技術を解明することもしくは解明を試みること」
- 「本サービスへのアクセスを防ぐまたは制限するために当社が使用することのある措置を回避すること」
- 「本サービスまたはその一部を別のプログラムや製品に組み込むこと」

また、違反があった場合、TikTok は単独の判断でサービスの提供を拒否し、アカウントを終了し、アクセスを制限できるとされています。

二次情報（規約の解説サイト）では、米国版の規約に「TikTok の書面による承認がない限り、自動化されたソフトウェアでデータを抽出してはならない」という趣旨の条項があるとされています（原文は**未確認**）。

### 2.4 考察

- 非公式ライブラリや中継サービスは、上記の「自動化されたスクリプトによる情報収集」「技術の解明」に、CAPTCHA の自動解決は「アクセス制限措置の回避」に、それぞれ該当する可能性があると考えます。
- 該当した場合、配信者のアカウントが停止・制限されるおそれがあります。オーバーレイの演出のためにアカウントを危険にさらすのは割に合わないと判断し、**本プロジェクトでは実装しません。**
- 非公式ツールを使った配信ツールは広く出回っていますが、「多く使われている」ことは「規約上問題がない」ことを意味しません。個々のツールについて TikTok が許可しているかは**未確認**です。
- 本レポートの判断は法的な見解ではありません。

## 3. 現在のシステムでの運用方法（D：配信者の手動操作）

管理パネル（`/admin`）から、配信者が自分の判断で操作します。

- 色演出の手動オーバーライド（割り込み再生も可）
- 視聴者全体へのメッセージ、コメントへの返答（定型文の返答候補から選択、または自由入力。表示前に自動チェック）
- 一時停止、スキップ、待ち分の破棄、全停止（緊急停止）

配信者の操作による演出は、画面に「配信者による演出」と表示し、ギフト通知の形式では表示できないようにしています（偽のギフト通知を作らないため）。

## 4. 将来の接続設計（E：公式の手段が得られた場合）

### 4.2 項目の対応（想定）

| 本システムの項目 | 想定する元データ | 注意点 |
|---|---|---|
| `giftId` / `giftName` | ギフトの ID・名称 | 名称は表示前にサニタイズされる |
| `tier`（normal / special） | ギフトの価値など | 価値に比例して演出を派手にしない（2段階のみ）。基準値は設定ファイルにする |
| `count` | 連続送信の回数 | 連続送信の途中経過と確定（終了）の区別に注意。途中経過を毎回加算すると数が重複する |
| `user.key` | 視聴者の内部 ID | そのまま保存せず、ハッシュ化した値を使うのが望ましい |
| `user.name` | 表示名 | 表示前にサニタイズ。不適切なら「視聴者」に置換 |
| コメント `text` | コメント本文 | 表示前にサニタイズ。ブロック時は本文をログに残さない |

### 4.3 実装時の技術的なハードル

- **提供条件**：利用申請・審査、利用目的の制限、回数制限、表示義務などがあれば、それに合わせた設計が必要
- **重複と順序**：再接続時のイベント重複、連続ギフトの途中経過と確定の扱い、到着順の入れ替わり
- **切断・遅延**：再接続（間隔を延ばしながら）、遅れて届いたイベントの扱い（古すぎるものは演出しない等）
- **負荷**：大規模配信ではイベントが非常に多くなる。現在のキューの上限・まとめ表示・コメント表示の間引きで吸収する前提だが、実データでの検証は**未実施**
- **個人情報**：視聴者 ID・表示名の保存期間と範囲を最小にする（現状はメモリ上のみ、最大5000人分、ログに本文を残さない）
- **年齢制限**：ギフトの送受信には年齢条件があるとされる（**未確認**）。ギフトを促す表示をしない方針は維持する
