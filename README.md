# 運命の波動神社（TikTok LIVE 向けオーバーレイ）

TikTok LIVE で、配信者本人の配信に重ねて使う**視聴者参加型エンターテインメント用の縦型オーバーレイ**です。
OBS のブラウザソースで読み込み、配信者は管理パネルから演出を操作します。

> 本コンテンツは娯楽目的です。結果は科学的根拠や将来を保証するものではありません（画面にも常時表示しています）。

**重要：現在は TikTok からの実イベント（実際のギフト・コメント）を受信しません。** 調査の結果、公式の取得手段が見つからず、非公式な方法は利用規約上の懸念が大きいためです（[調査レポート](docs/integration-research.md)）。画面の演出は、テストUIからのシミュレーションか、管理パネルでの配信者の操作によって動きます。

## 起動方法

Node.js 18 以上が必要です。

```bash
npm install
cp .env.example .env   # 設定を編集（.env は Git 管理外）
npm start              # 開発時は npm run dev（ファイル変更で自動再起動）
npm test               # 自動テスト
```

起動するとコンソールに次のように表示されます。

```
[INFO] 運命の波動神社 overlay（OBS用）: http://127.0.0.1:3000/
[INFO] 管理パネル:                      http://127.0.0.1:3000/admin
[INFO] テストUI付きオーバーレイ:        http://127.0.0.1:3000/?test=1
[INFO] 管理用トークン（今回の起動のみ有効）: xxxxxxxxxxxxxxxxxxxxxxxx
[INFO] [SIMULATION] 現在はシミュレーションモードです。TikTok からの実イベントは受信していません。
```

`.env` の `ADMIN_TOKEN` を設定していない場合、管理用トークンは起動のたびに変わります。毎回入力し直したくない場合は、`ADMIN_TOKEN` に16文字以上の推測されにくい値を設定してください。

### 設定項目（`.env`）

| 項目 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `127.0.0.1` | 待ち受けアドレス。既定ではこの PC からのみアクセス可能 |
| `ADMIN_TOKEN` | （空） | 管理パネル・テストUIの操作に必要なトークン。空ならランダム生成 |
| `ADMIN_ALLOW_REMOTE` | `false` | `true` のときだけ、この PC 以外からの管理接続を許可 |
| `MESSAGE_HISTORY_SIZE` | `10` | 色ごとに、直近何件のメッセージと重複させないか |
| `COMMAND_COOLDOWN_SEC` | `30` | コメントでの色指定・おみくじの、視聴者ごとの再実行間隔（秒） |
| `EVENT_MODE` | `simulation` | `simulation` のみ対応（他の値でも simulation で起動し、警告を表示） |

## URL とパラメータ

| URL | 用途 | 操作権限 |
|---|---|---|
| `http://127.0.0.1:3000/` | **OBS に読み込む画面** | 受信のみ（画面から何も送信しない） |
| `http://127.0.0.1:3000/admin` | 管理パネル（配信中の操作） | トークン必須 |
| `http://127.0.0.1:3000/?test=1` | テストUI付きオーバーレイ（動作確認用） | 送信にはトークン必須 |

オーバーレイ（`/`）の URL パラメータ（`&` でつないで組み合わせ可能）：

| パラメータ | 効果 | 使う場面 |
|---|---|---|
| `test=1` | 画面右上にテストUIを表示 | ブラウザでの動作確認。**OBS 用の URL には付けない** |
| `transparent=1` | 背景（夜空・月・参道）を透過し、鳥居・演出・文字だけを表示 | カメラ映像の上に重ねたいとき |
| `disclaimer=top` | 免責注記を画面上部へ移動 | TikTok アプリの下部の表示（コメント欄など）と重なる場合 |

例：カメラに重ねて、免責注記を上に置く場合

```
http://127.0.0.1:3000/?transparent=1&disclaimer=top
```

## OBS での設定手順

ここでは OBS Studio を例に説明します。メニュー名は OBS のバージョンや言語設定によって多少異なります。

### 1. 縦型のキャンバスにする

1. OBS の「設定」→「映像」を開く。
2. 「基本（キャンバス）解像度」を `1080x1920` にする（PC の負荷が高い場合は `720x1280`）。
3. 「出力（スケーリング）解像度」も同じ値にする。
4. 「OK」で閉じる。

### 2. サーバーを起動する

配信用 PC で `npm start` を実行し、コンソールに URL とトークンが表示されることを確認します。OBS を使っている間は、このコンソールを閉じないでください。

### 3. ブラウザソースを追加する

1. 「ソース」の「＋」→「ブラウザ」を選び、名前（例：`波動神社`）を付けて「OK」。
2. 次のように設定する。

| 項目 | 設定値 |
|---|---|
| URL | `http://127.0.0.1:3000/`（カメラに重ねる場合は `http://127.0.0.1:3000/?transparent=1`） |
| 幅 / 高さ | キャンバスと同じ：`1080` / `1920`（720p なら `720` / `1280`） |
| カスタムフレームレートを使用 | オフ（OBS の設定に従う） |
| カスタム CSS | 空にする（既定の CSS が入っている場合は削除）。このページはセキュリティ設定（CSP）により外部から差し込まれたスタイルを受け付けないため、カスタム CSS は効かない場合があります。背景の透過は `?transparent=1` で行います |
| ソースが表示されていないときにシャットダウン | オフ（演出の状態を保つため） |
| シーンがアクティブになったときブラウザの表示を更新 | オフ |

3. 「OK」で閉じ、ソースがキャンバス全体を覆っていることを確認する（ずれている場合は、ソースを右クリック→「変換」→「画面に合わせる」）。

画面は 1080x1920 を基準に作られており、幅・高さに合わせて自動で縮小されます。9:16 以外の大きさにした場合は、上下または左右に余白ができます。

### 4. カメラと重ねる場合

1. カメラ（映像キャプチャデバイス）のソースを、ブラウザソースより**下**に置く。
2. ブラウザソースの URL を `?transparent=1` 付きにする。
3. 鳥居と演出が顔に重なる場合は、カメラの位置・大きさを調整する。

TikTok では、配信者が映らない静止画・ループ映像だけの配信は低品質な LIVE と扱われる可能性があると第三者情報で報じられています（公式本文は未確認）。このオーバーレイは、**配信者本人の配信を補助する用途**で使ってください。

### 5. 動作を確認する

1. PC のブラウザで `http://127.0.0.1:3000/admin` を開き、コンソールに表示されたトークンでログインする。
2. ヘッダーの「OBS画面 1台接続」を確認する（OBS のブラウザソースが接続されている）。
3. 「テスト（シミュレーション）」の「テストギフト（通常）」を押し、OBS のプレビューに `【テスト】` 付きの演出が出ることを確認する。
4. 「全停止（緊急停止）」を2回押して画面が消えること、「再開」で戻ることを確認する。

### 6. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 何も表示されない・真っ黒 | サーバーが起動しているか。URL のポート番号が `.env` の `PORT` と同じか。ソースを右クリック→「プロパティ」で「現在のページを再読み込み」 |
| 画面が小さい・ずれている | ブラウザソースの幅・高さがキャンバスと同じか。「変換」→「画面に合わせる」 |
| 背景が透けない | URL に `?transparent=1` が付いているか。カスタム CSS が空か |
| テストUIが映っている | OBS の URL から `test=1` を外す |
| 管理パネルにログインできない | トークンがコンソール表示（または `.env`）と同じか。サーバー再起動でトークンが変わっていないか。失敗が10回続くと約1分間接続できません |
| 「OBS画面 0台接続」 | OBS のブラウザソースの URL が正しいか。ソースのプロパティで再読み込み |

### 7. TikTok への配信について

OBS から TikTok LIVE へ配信する方法（ストリームキーの取得可否、TikTok LIVE Studio の利用など）は、アカウントの状態や地域によって異なります。TikTok の公式ヘルプで最新の手順を確認してください（本プロジェクトでは**未確認**）。

## 管理パネルの使い方

`http://127.0.0.1:3000/admin` を、配信用 PC のブラウザで開きます。

| 区画 | できること |
|---|---|
| ヘッダー | 動作モード（シミュレーション）、運転状態（稼働中／一時停止中／全停止中）、接続中の OBS 画面の数 |
| 配信制御 | **一時停止**：新しい演出とコメント表示を止める（再生中の演出は最後まで流れる。届いたイベントは上限まで待機）<br>**再開**<br>**スキップ**：再生中の演出を終えて次へ<br>**待ち分を破棄**：待機中の演出とコメント表示を捨てる<br>**全停止（緊急停止）**：待機分を捨て、再生中の演出も止めて画面を消去。再開まで、配信者の操作以外のイベントを受け付けない。押し間違い防止のため**2回押し**で実行 |
| 手動オーバーライド | 10色のボタンで色演出を出す。分類（おみくじ・前向きな言葉など）を指定可能。「割り込み」で再生中の演出を打ち切って即再生（一時停止中・全停止中でも再生できる） |
| 配信者からのメッセージ | 視聴者全体へのメッセージ、またはコメントへの返答（宛先を入れた場合）を画面に表示。60文字まで。表示前に NG 語・URL・個人情報らしき文字列を自動チェックし、引っかかったら表示しない |
| コメントと返答候補 | 届いたコメント（サニタイズ済み）と、定型文の返答候補3つを表示。候補をクリックするとメッセージ欄に入る（自動では画面に出ない）。フィルターで止めたコメントは理由だけを表示し、本文は表示しない |
| 設定 | ギフト演出、コメントの画面表示、コメントでの色指定・おみくじを個別にオン／オフ |
| テスト（シミュレーション） | テストギフト・テストコメントを送る（画面とログに「テスト」と表示される） |
| ログ | 直近100件の操作・イベント（`[SIMULATION]` / `[OPERATOR]` / `[LIVE]`）。視聴者のコメント本文は含まない |

配信者の操作による演出は、画面に **「配信者による演出」** と表示されます。管理パネルからはギフト通知の形式の表示は作れません（偽のギフト通知を作らないため）。

返答候補は `src/data/replyTemplates.json` の定型文から選ばれます（生成 AI は使っていません）。あいさつ・お別れ・感謝・ほめ言葉・質問・色指定・おみくじ・その他に分類して候補を出します。文面は自由に編集できます。

## セキュリティ

| 対策 | 内容 |
|---|---|
| 待ち受けアドレス | 既定は `127.0.0.1`（この PC からのみ）。`HOST` を変えると警告を表示 |
| 管理接続の制限 | 管理パネルのページと管理用ソケットは、既定でループバック（この PC）以外からの接続を拒否（`ADMIN_ALLOW_REMOTE=true` で解除） |
| トークン認証 | 管理操作・テスト送信にはトークンが必要。比較はタイミング差が出ない方式。10回失敗した接続元は約1分間ブロック |
| Origin 確認 | 別のサイトのページから管理用ソケットに接続させる攻撃を防ぐため、ブラウザからの接続は Origin が一致する場合のみ許可 |
| OBS 画面は受信専用 | `/` の接続からは何も操作できない（以前のバージョンでは認証なしでテスト送信できたが、廃止） |
| セキュリティヘッダー | Content-Security-Policy（同一オリジンのスクリプト・スタイルのみ）、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer` |
| 入力の制限 | 受信データの大きさ（16KB）、テスト送信（毎秒300件）・管理操作（毎秒20件）の上限、許可した項目以外は破棄 |
| 表示の安全 | 画面・管理パネルとも、視聴者由来の文字列は `textContent` でのみ挿入 |
| 秘密情報 | トークンなどは `.env` から読み込み、ソースコードに書かない。トークンはブラウザの `sessionStorage`（タブを閉じると消える）に保存 |

**この PC 以外（スマートフォンなど）から管理パネルを使う場合**：`HOST` を LAN 内のアドレス（例：`192.168.x.x`）、`ADMIN_ALLOW_REMOTE=true`、`ADMIN_TOKEN` を長い値に設定してください。通信は暗号化されない（HTTP）ため、**信頼できる家庭内 LAN でのみ**使い、ルーターのポート開放などでインターネットに公開しないでください。

## 画面と演出

### 画面構成（1080x1920 基準）

- 上部：タイトル、右上にモード表示（`シミュレーションモード（実イベント未接続）`）
- 中央：鳥居と「波動の鏡」。演出時は色ごとのオーラ・波紋・光の粒子
- 下部：メッセージカード（見出し・色名・分類・本文・出どころの札）
  - テストの演出：`テスト演出（シミュレーション）`（黄色）
  - 配信者の操作：`配信者による演出`（水色）
- カードの下：コメント表示（最大3件。サニタイズ済みの文字列のみ。テストのコメントには `テスト` の札）
- 最下部：免責注記（常時表示。非表示にする設定は意図的に用意していません）

### 波動カラー10種

各色で粒子の形・動き、波紋、オーラ、背景、文字アニメーションを個別に定義しています（`public/js/themes.js`、`public/css/overlay.css`）。

| 色 | 意味 | 粒子 | 波紋 | オーラ | 文字 |
|---|---|---|---|---|---|
| ゴールド | 豊かさ・感謝 | 四芒星が上昇・瞬き | 細いリング | 回転する光条 | 金色の光沢が流れる |
| パープル | 直感 | 光球が渦を描く | 太く柔らかい波 | 脈動 | ぼかしから浮かび上がる |
| グリーン | 癒やし | 木の葉が揺れながら舞う | 細い波が5重 | ゆっくり呼吸 | ふわっと浮上し漂う |
| ピンク | 愛情 | ハートが浮かぶ | 二重リング | 鼓動 | 1文字ずつポップ |
| ブルー | 冷静さ | 雫が降る | 水面の楕円波紋 | きらめき | タイプライター |
| レッド | 勇気 | 火の粉が揺らめき上昇 | 衝撃波 | 炎の揺らぎ | 拡大＋発光 |
| ホワイト | リセット | 雪の結晶が舞い降りる | 白い閃光 | 放射して消える | 白い光から現れる |
| アクア | 変化 | 泡が揺れながら上昇 | 揺らぐ楕円 | 形が変化 | 文字が波打つ |
| オレンジ | 創造性 | 紙吹雪が弾ける | 回転する破線 | 破線リングが回転 | 1文字ずつ跳ねる |
| レインボー | 祝福 | 七色の星が弾ける | 七色の多重リング | 虹色の輪が回転 | 虹色グラデーション |

### メッセージデータ

- `src/data/messages.json`：10色 × 6分類（今日のおみくじ／前向きな言葉／問いかけ／感謝／挑戦への応援／みんなへの祝福）× 5件 ＝ 各色30件・計300件（すべてオリジナル文面）。
- 色ごとに直近 N 件（`MESSAGE_HISTORY_SIZE`）と重複しないように抽選します。
- 文面ルール：不安をあおる表現、災いの予告、金銭・健康・恋愛などの結果の保証、ギフトを促す表現は入れない。`npm test` で禁止語の機械チェックを行いますが、**最終確認は人の目で行ってください**。

## イベント処理

### 処理の流れ

```
テストUI・管理パネル ──(/admin ソケット：トークン必須)──┐
   sim:*   → simulationSource → createSimulationEvent()   origin=simulation
   admin:* → adminSource      → createOperatorEvent()     origin=operator（ギフト形式は作れない）
（将来）実連携アダプタ liveSource（未実装）→ createLiveEvent() origin=live
                                                          ▼
                     EventRouter：運転状態・設定の確認、入力検証・サニタイズ、コマンド解析、返答候補
                         │                     │                         │
                    EffectQueue           CommentFeed               管理パネルへ通知
                   （1件ずつ再生）          （間引き）           （コメント・返答候補・ログ・状態）
                         ▼                     ▼
          OBS 画面（/ ソケット：受信専用）  play / play:update / play:end / comment / stop
```

### 演出キュー（`src/lib/effectQueue.js`）

- メイン演出は常に1件ずつ再生し、終了後 0.6 秒の間隔を空けて次へ進みます（重なりなし）。
- 優先度：特別ギフト・配信者の操作（high）＞ 通常ギフト・テストの手動演出（normal）＞ コメント由来の演出（low）。
- 待ち時間が 20 秒を超えた低優先度の項目は1件だけ先に出し、次は通常の優先度順に戻します。
- 同じ視聴者×同じギフトの連続は1つにまとめ、「×10」のようにカウントを加算します（再生中ならカウントを更新し、表示を最大6秒延長）。
- 待機数に応じて表示時間を短縮します（5件以上 ×0.75、10件以上 ×0.55、20件以上 ×0.4、下限 2.2 秒）。
- レーン上限（high 10 / normal 20 / low 10）を超えたギフトは「たくさんの応援ありがとうございます（N件）」1件に集約し、コメント由来の演出は破棄します。
- 割り込み再生（配信者の手動オーバーライド）は、一時停止中でも再生されます。

### コメントの検証とフィルター（`src/lib/sanitize.js`、`src/data/ngwords.json`）

画面に送るのは、次の検査を通過した文字列だけです。引っかかった場合は元の文字列を返さず、ログ・管理パネルにも理由コードと文字数だけを残します。

| 検査 | 内容 | 理由コード |
|---|---|---|
| 正規化 | NFKC、制御文字・ゼロ幅文字・方向制御文字・タグ文字の除去、結合文字の連打の抑制、空白の整理、同じ文字5連続以上を3文字に圧縮、長さの制限（コメント40字・名前14字・配信者メッセージ60字） | — |
| HTML・スクリプト | タグ、`javascript:`、`onXXX=`、文字参照など | `markup` |
| URL | `http(s)://`、`www.`、主なドメイン末尾 | `url` |
| 個人情報らしきもの | 8桁以上の数字の並び、メールアドレス、郵便番号、番地・丁目、SNS の ID の聞き出し、`@ユーザー名` | `pii:*`, `mention` |
| 不適切な表現 | 嫌がらせ・暴力・自傷・差別・性的表現。日本語は表記どおりの部分一致（空白・記号を挟む回避も検出）、英語は単語単位（分かち書き・数字置き換えも検出）。誤検知しやすい語は例外リストで除外 | `ng:*` |

- タグではない `<` `>` `&` などは全角文字に置き換えて表示します。
- 不適切な表示名は「視聴者」に置き換え、ギフト演出自体は続けます。
- コメント表示は 0.8 秒に1件まで間引き、待ちが20件を超えたら古いものから捨てます。
- **機械的なフィルターには誤検知・見逃しがあります。** NG ワードは運用しながら `src/data/ngwords.json` に追加・調整してください。

### コメントでの参加

- **色を選ぶ**：「ゴールド」「パープル」「青」「虹色」「pink」などを含むコメントで、その色の控えめな演出を再生します。選んだ色は、その視聴者のあとのギフト演出にも使われます。
- **今日のおみくじ**：「おみくじ」を含むコメントで、おみくじ分類のメッセージを表示します。
- 視聴者ごとに再実行まで 30 秒の待ち時間があります。一文字の色（「青」「金」など）はコメント全体がその語のときだけ反応します。

### 出どころの区別

| 出どころ | 生成元 | 画面の表示 | ログ |
|---|---|---|---|
| シミュレーション | テストUI・管理パネルのテスト欄 | `【テスト】`付きの名前、`（テスト）`付きのギフト名、`テスト演出（シミュレーション）`、コメントに `テスト` 札 | `[SIMULATION]` |
| 配信者の操作 | 管理パネル | `配信者による演出`、`配信者からのメッセージ` / `〇〇さんへ` | `[OPERATOR]` |
| 実イベント | （未実装） | 札なし | `[LIVE]` |

- 出どころは受け取ったモジュールで固定され、受信データ内の `origin` や `simulated` は無視します。テストUIから実イベントや配信者の操作を装うことはできません。
- シミュレーションと実イベントは、同じ視聴者・同じギフトでもまとめません。

## 安全・透明性の方針と TikTok ガイドライン

### 方針

- 実際の TikTok イベントとの連携は行っていません。画面右上と起動ログにシミュレーションモードであることを明示します。
- テストの演出は画面に `テスト`、ログに `[SIMULATION]` と必ず表示し、実ギフトとして表示する経路はありません。テスト用の視聴者名は必ず `【テスト】` 付きです。
- 偽のギフト通知・存在しない視聴者の反応は生成しません。配信者の操作でもギフト通知の形式は作れません。
- ギフトを促す文言・ランキング・目標額・カウントダウンは表示しません。ギフトの額に応じて演出を派手にしません（通常／特別の2段階のみ）。
- 免責注記を常時表示し、メッセージは断定・保証表現を避けています。
- AI 検知の回避、禁止行為の隠蔽、検知をすり抜ける仕組みは実装していません。

### TikTok ガイドラインの確認状況

LIVE 関連のガイドライン本文は、公式ページが JavaScript 描画のため取得できず、**一次情報での確認は未完了**です。利用規約（日本語版）と開発者製品一覧は一次情報を取得しました（[調査レポート](docs/integration-research.md)）。

| 論点 | 対応 | 状態 |
|---|---|---|
| ギフトの直接的な要求、ギフトと結び付いたカウントダウン等は「要求行為」とみなされうる（第三者情報） | ギフト誘導の文言・カウントダウンを置かない | 方針として対応、公式本文は未確認 |
| 静止画・無人・ループ映像のみの LIVE は低品質扱い（第三者情報） | 配信者本人の配信の補助として使う前提を明記 | 未確認 |
| ギフトの送受信は 18 歳以上が条件とされる（第三者情報） | ギフトを促す表示をしない | 未確認 |
| ギフトへのお礼表示がギフトを促す行為にあたるか | 感謝表示にとどめ、ランキング・目標額は置かない | 未確認 |
| 占い・運勢表現の扱い | 娯楽である旨を常時表示し、断定・保証表現を避ける | 規定の有無は未確認 |
| 自動化されたスクリプトによる情報収集など（利用規約第5条、一次情報） | 非公式ライブラリによる自動連携を実装しない | 対応済み（規約の解釈は法的見解ではない） |

本プロジェクトは規約への適合を保証するものではありません。配信前に、利用時点の TikTok 公式ガイドラインを配信者ご自身で確認してください。

## 実連携について

詳細は [docs/integration-research.md](docs/integration-research.md) を参照してください。要点：

- 調査時点で、LIVE のコメント・ギフトを取得する**公式 API は提供されていません**（TikTok for Developers の製品一覧で確認）。
- 非公式ライブラリ（TikTok-Live-Connector 等）は内部通信を解析して接続するもので、利用規約第5条で禁止されている「自動化されたスクリプトによる情報収集」「技術の解明」「アクセス制限措置の回避」に該当する可能性があるため、**本プロジェクトでは使いません**。
- 現在は、配信者が管理パネルで手動で演出・返答を出す運用です。
- 公式の手段が提供された場合に備え、`src/sources/liveSource.js` に接続口（アダプタ）の仕様を記載しています。キュー・フィルター・表示はすでに実イベントに対応しています。

### 長時間稼働のための設計

- 粒子（最大700）・波紋（最大32）はオブジェクトプールで再利用。粒子の見た目は事前描画してキャッシュ（最大80枚）。演出がない間は 30fps に間引き。
- 画面：コメント表示は最大3件、テストログ40行。管理パネル：コメント50件、ログ100件。
- サーバー：キューのレーン上限、コメント待ち20件、視聴者ごとの状態（最大5000人）、管理パネル向けの保持（コメント50件・ログ100件）に上限あり。
- 確認結果：毎秒ギフト3件＋コメント5件を5分間送り続けた試験で、ブラウザの JS ヒープ 0.9MB → 1.3MB（1分後以降は横ばい）、サーバーのメモリ 66〜67MB で一定。数時間単位の試験は未実施。

## 未実装・既知の制限

- **TikTok 実イベントの自動受信は未実装**です（公式の手段が確認できるまで実装しない方針）。
- 実機の OBS・TikTok LIVE（アプリ上の見え方、コメント欄などと重なる領域）での確認は未実施です。
- 数時間単位の連続稼働試験は未実施です。
- NG ワード・個人情報の判定は簡易的で、誤検知・見逃しがあります（例：漢数字の電話番号、言い換え表現）。
- 過負荷時、レーン上限を超えたギフトは個別には表示されず「まとめ」に集約されます。コメント由来の演出は破棄されます。上限超過のログが多く出ることがあります。
- 管理パネルは HTTP（暗号化なし）です。この PC 以外から使う場合は信頼できる LAN 内に限ってください。
- 返答候補は定型文の選択のみで、文脈の理解はしません。
- 管理パネルの設定（オン／オフ）はサーバーを再起動すると初期値に戻ります。
- 配信者向けの文言（返答候補・メッセージ）は自分で確認・編集してください。自動チェックは補助です。
