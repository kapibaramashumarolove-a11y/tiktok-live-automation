# 運命の波動神社（TikTok LIVE 向けオーバーレイ）

TikTok LIVE で、配信者本人の配信に重ねて使う**視聴者参加型エンターテインメント用の縦型オーバーレイ**です。
OBS のブラウザソースで読み込んで使います。

> 本コンテンツは娯楽目的です。結果は科学的根拠や将来を保証するものではありません（画面にも常時表示しています）。

## 起動方法

Node.js 18 以上が必要です。

```bash
npm install
cp .env.example .env   # 必要に応じて編集（.env は Git 管理外）
npm start              # 開発時は npm run dev（ファイル変更で自動再起動）
npm test               # 単体テスト（メッセージデータ検証・抽選ロジック）
```

起動すると次の URL が使えます（既定ポート 3000）。

| URL | 用途 |
|---|---|
| `http://127.0.0.1:3000/` | OBS 用（テストUIなし） |
| `http://127.0.0.1:3000/?test=1` | 動作確認用（画面右上にテストUIを表示） |

URL パラメータ（組み合わせ可）:

- `test=1` … テストUIを表示。**OBS に読み込む URL には付けないでください。**
- `transparent=1` … 背景（夜空・月・参道）を透過し、カメラ映像の上に重ねて使えるようにします。
- `disclaimer=top` … 免責注記を画面上部に移動（TikTok アプリのコメント欄と重なる場合の回避用）。

## OBS での設定（基本）

1. OBS の「ソース」→「＋」→「ブラウザ」を追加。
2. URL に `http://127.0.0.1:3000/` を入力（カメラに重ねる場合は `/?transparent=1`）。
3. 幅 `1080`・高さ `1920`（または `720` × `1280`）を指定。画面は 9:16 に自動で等倍縮小されます。
4. OBS の「設定」→「映像」で基本解像度・出力解像度を縦型（例：1080x1920）にします。
5. 演出を確認したいときは、別のブラウザで `/?test=1` を開いてボタンを押すと、OBS 側の画面にも同じ演出が出ます（どちらにも「テスト演出（シミュレーション）」と表示されます）。演出の順番はサーバー側のキューで管理しているため、OBS とテスト用ブラウザで同じ順序になります。

※ 配信者が映らない静止画・ループ映像のみの配信は、TikTok で低品質な LIVE と扱われる可能性があると第三者情報で報じられています（公式本文は未確認）。本オーバーレイは**配信者本人の配信を補助する用途**を想定しています。

詳細な OBS 手順（シーン構成、音声、セーフエリア）はフェーズ3で追記予定です。

## 画面構成（1080x1920 基準）

- 上部：タイトル「運命の波動神社」、右上にモード表示（`シミュレーションモード（実イベント未接続）`）
- 中央：鳥居と「波動の鏡」。演出時は色ごとのオーラ・波紋・光の粒子
- 下部：メッセージカード（見出し・色名・分類・本文）。テスト由来の演出には `テスト演出（シミュレーション）` の札を表示
- カードの下：コメント表示（最大3件。サニタイズ済みの文字列のみ。テストのコメントには `テスト` の札）
- 最下部：免責注記（常時表示。非表示にする設定は意図的に用意していません）

## メッセージデータ

- `src/data/messages.json`：10色 × 6分類（今日のおみくじ／前向きな言葉／問いかけ／感謝／挑戦への応援／みんなへの祝福）× 5件 ＝ **各色30件・計300件**（すべてオリジナル文面）。
- 抽選（`src/lib/messagePicker.js`）：色ごとに直近 N 件（`.env` の `MESSAGE_HISTORY_SIZE`、既定10）の履歴を持ち、その範囲での重複を避けます。分類指定時に候補数が N 以下でも、直前と同じ文が続かないようにしています。
- 文面ルール：不安をあおる表現、災いの予告、金銭・健康・恋愛などの結果の保証、ギフトを促す表現は入れない。`npm test` で禁止語の機械チェックを行いますが、**最終確認は人の目で行ってください**。

## イベント処理（フェーズ2）

### 処理の流れ

```
テストUI ──(Socket.IO: sim:gift / sim:comment / sim:effect)──> simulationSource
                                                                 │ createSimulationEvent()  ← origin=simulation に固定
（将来）実連携アダプタ ── liveSource（未実装） ── createLiveEvent() ┘
                                                                 ▼
                                    EventRouter：入力検証・サニタイズ・コマンド解析
                                       │                         │
                                  EffectQueue               CommentFeed（間引き）
                                  （1件ずつ再生）               │
                                       ▼                         ▼
                           play / play:update / play:end       comment   → 画面
```

### 演出キュー（`src/lib/effectQueue.js`）

- メイン演出は常に1件ずつ再生し、終了後 0.6 秒の間隔を空けて次へ進みます（重なりなし）。
- 優先度：特別ギフト（high）＞ 通常ギフト・手動演出（normal）＞ コメント由来の演出（low）。
- 待ち時間が 20 秒を超えた低優先度の項目は1件だけ先に出し、次は通常の優先度順に戻します（取り残しと占有の両方を防止）。
- 同じ視聴者×同じギフトの連続は1つにまとめ、「×10」のようにカウントを加算します。再生中なら画面のカウントだけを更新し、表示を最大6秒まで延長します。
- 待機数に応じて1件あたりの表示時間を短縮します（5件以上 ×0.75、10件以上 ×0.55、20件以上 ×0.4、下限 2.2 秒）。
- レーン上限（high 10 / normal 20 / low 10）を超えたギフトは、レーン末尾の「たくさんの応援ありがとうございます（N件）」1件に集約します。コメント由来の演出は上限を超えたら破棄します。
- 一時停止・スキップ・待機分の破棄・全停止の機能はキュー側にありますが、操作UI（管理パネル）はフェーズ3で作ります。

### コメントの検証とフィルター（`src/lib/sanitize.js`、`src/data/ngwords.json`）

画面に送るのは、次の検査を通過した文字列だけです。引っかかった場合は元の文字列を返さず、ログにも理由コードと文字数だけを残します（本文は保存しません）。

| 検査 | 内容 | 理由コード |
|---|---|---|
| 正規化 | NFKC（全角英数→半角など）、制御文字・ゼロ幅文字・方向制御文字・タグ文字の除去、結合文字の連打（Zalgo）の抑制、空白の整理、同じ文字5連続以上を3文字に圧縮、長さの制限（コメント40字・名前14字） | — |
| HTML・スクリプト | タグ、`javascript:`、`onXXX=`、文字参照など | `markup` |
| URL | `http(s)://`、`www.`、主なドメイン末尾 | `url` |
| 個人情報らしきもの | 8桁以上の数字の並び（電話番号など）、メールアドレス、郵便番号、番地・丁目、SNS の ID の聞き出し、`@ユーザー名` | `pii:*`, `mention` |
| 不適切な表現 | 嫌がらせ・暴力・自傷・差別・性的表現。日本語は表記どおりの部分一致（空白・記号を挟む回避も検出）、英語は単語単位（`f u c k`、`sh1t` のような回避も検出）。誤検知しやすい語は例外リストで除外 | `ng:*` |

- タグではない `<` `>` `&` などは全角文字に置き換えて表示します。画面側でも必ず `textContent` で挿入します（二重の防御）。
- 不適切な表示名は「視聴者」に置き換え、ギフト演出自体は続けます。
- コメント表示は 0.8 秒に1件まで間引き、待ちが20件を超えたら古いものから捨てます。
- **機械的なフィルターには誤検知・見逃しがあります。** NG ワードは運用しながら `src/data/ngwords.json` に追加・調整してください。

### コメントでの参加

- **色を選ぶ**：「ゴールド」「パープル」「青」「虹色」「pink」などを含むコメントで、その色の控えめな演出（粒子・波紋を半分）を再生します。選んだ色は、その視聴者のあとのギフト演出にも使われます。
- **今日のおみくじ**：「おみくじ」を含むコメントで、おみくじ分類のメッセージを表示します。
- 視聴者ごとに再実行まで 30 秒の待ち時間があります（`.env` の `COMMAND_COOLDOWN_SEC`）。
- 一文字の色（「青」「金」など）はコメント全体がその語のときだけ反応します（「青春」「金曜日」では反応しない）。

### シミュレーションと実イベントの区別

- イベントの出どころ（`origin`）は受け取ったモジュールで固定され、受信データ内の `origin` や `simulated` は無視します。テストUIから「実イベント」を装うことはできません。
- シミュレーションのイベントは、ID が `sim-` で始まり、視聴者キーは `sim:` 付き、表示名には `【テスト】`、ギフト名には `（テスト）` が必ず付きます。
- 画面：右上の `シミュレーションモード（実イベント未接続）`、演出カードの `テスト演出（シミュレーション）`、コメントの `テスト` 札。
- ログ：`[SIMULATION]` / `[LIVE]` のタグで区別します。
- シミュレーションと実イベントは、同じ視聴者・同じギフトでも別々に扱い、まとめません。
- 実イベントの受信経路（`src/sources/liveSource.js`）は未実装で、呼び出すとエラーになります。

### テストUI（`/?test=1`）の操作

| ボタン | 内容 |
|---|---|
| 通常ギフト / 特別ギフト | テスト用ギフトを1件発生 |
| 連続ギフト ×10 | 同じ視聴者が150ms間隔で10回（1つの演出にまとまることを確認） |
| 同時ギフト ×20 | 20人が同時に送った状況（順番に再生されることを確認） |
| 大量ギフト ×100 | 上限超過時のまとめ表示を確認 |
| 混在 ×40 | ギフトとコメント（NG例を含む）が交互に届く状況 |
| 入力例 / コメント送信 | HTML・URL・電話番号・住所・NG語などの例を送り、表示可否と理由をログで確認 |
| コメント連投 ×30 | コメント表示の間引きを確認 |

パネル上部に、キューの状態（待機数・速度倍率・まとめ数・破棄数・非表示コメント数など）を表示します。

## 安全・透明性の方針

- 実際の TikTok イベントとの連携は**未実装**です。サーバーは常にシミュレーションモードで動き、起動ログと画面右上に明示します（`EVENT_MODE=live` を指定しても警告を出して simulation で起動します）。
- テストUIから発生させた演出は、画面に `テスト演出（シミュレーション）`・`【テスト】`、サーバーログに `[SIMULATION]` と必ず表示します。実ギフトとして表示する経路はありません。
- テスト用の視聴者名は必ず `【テスト】` 付きで表示し、実在の視聴者の反応と誤認されないようにしています。
- 偽のギフト通知・存在しない視聴者の反応は生成しません。ギフトを促す文言・カウントダウン等も表示しません。
- 画面に表示する文字列はすべて `textContent` で挿入しています（HTML として解釈しません）。

## 長時間稼働のための設計

- 粒子（最大700）・波紋（最大32）はオブジェクトプールで再利用し、上限を超えて増えません。
- 粒子の見た目は色×形ごとに事前描画してキャッシュ（最大80枚）。
- 演出がない間は描画を 30fps に間引き。
- テストログは最大40行、コメント表示は最大3件、メッセージは都度置き換えで DOM が増え続けないようにしています。
- サーバー側も、キュー（レーン上限）、コメント待ち（20件）、視聴者ごとの状態（最大5000人、古い順に削除）に上限があります。
- テストUIからの入力は1接続あたり毎秒300件までに制限しています。
- 確認結果（フェーズ1）：2 秒ごとに演出を 90 回発生させた 3 分間の試験で、JS ヒープ約 1.7MB → 2.1MB、DOM ノード数は 280〜420 の範囲で推移。
- 確認結果（フェーズ2）：毎秒ギフト3件＋コメント5件を 5 分間送り続けた試験で、ブラウザの JS ヒープ 0.9MB → 1.3MB（1分後以降は横ばい）、サーバーのメモリ 66〜67MB で一定、エラーなし。
- 数時間単位の連続稼働試験は未実施です。
